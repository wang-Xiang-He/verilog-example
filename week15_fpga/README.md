## 一、★ 完整流程：三行指令

```
    你的 .v
       ↓  yosys           綜合：RTL → LUT/DFF 網表
    .json
       ↓  nextpnr-ice40   佈局繞線：決定每個 LUT 擺哪、線怎麼走
    .asc                  （順便做時序分析）
       ↓  icepack         打包成晶片認得的位元流
    .bin   ★ 這就是可以燒進去的檔案
       ↓  icetime         靜態時序分析報告
    .rpt
```

`build.bat` 就是把這四步包起來。**對照課本 2.5 節那 40 頁 Vivado 截圖**，
做的是完全同一件事。

| 檔案 | 是什麼 |
|---|---|
| `.json` | 綜合後的網表（給 nextpnr 吃） |
| `.asc` | 佈局繞線結果（**純文字，可以打開看**） |
| `.bin` | ★ bitstream，燒進晶片的就是這個 |
| `.rpt` | 靜態時序分析報告 |

## 二、`.pcf` 腳位約束檔

```
set_io clk        J3
set_io led[0]     B5
set_io uart_tx    B12
```

**它在回答一個問題**：你 Verilog 裡叫 `led` 的那條線，接到晶片哪一支腳？

> [!IMPORTANT]
> **★ 設計裡每一個輸出入埠都必須有一行**，少一個 nextpnr 直接報錯：
> ```
> ERROR: IO 'heartbeat' is unconstrained in PCF
> ```
> 這是好事 —— 總比讓工具亂接一支腳好。

**做這份教材時真的踩到的兩個坑：**

1. **向量要一位一位寫**
   `led[7:0]` 不能寫 `set_io led B5`，要寫 8 行 `set_io led[0] B5` …

2. **腳位名稱不是隨便編的**
   我一開始寫了 `N1`，結果：
   ```
   ERROR: package does not have a pin named 'N1'
   ```
   ct256 封裝只有 207 支腳，`N1` 不在裡面。查法：
   ```
   awk '/^\.pins ct256/{f=1;next} /^\./{if(f)exit} f{print $1}' \
       D:\oss-cad-suite\share\icebox\chipdb-8k.txt
   ```

> [!WARNING]
> ⚠️ 腳位**每塊板子都不一樣**，一定要查你手上那塊的電路圖。
> 接錯輕則不動，**重則兩支腳對灌燒掉**。

## 三、本週五個範例與實測結果

| 範例 | 頂層模組 | 邏輯單元 | 最高時脈 | bitstream |
|---|---|---:|---:|---:|
| `01_blink` | `blink` | 35 | 150.84 MHz | 135,100 B |
| `02_pwm` | `pwm` | 72 | 153.27 MHz | 135,100 B |
| `03_button` | `button_counter` | 62 | 176.41 MHz | 135,100 B |
| `04_seg7` | `seg7_top` | **402** | **19.29 MHz** | 135,100 B |
| `05_uart_tx` | `uart_tx_top` | 86 | 150.05 MHz | 135,100 B |

> **bitstream 大小都一樣**是正常的 —— iCE40 的位元流是**固定長度**，
> 不管你的設計多大多小，整顆晶片的組態資料都要寫一遍。

### 📁 `01_blink` — LED 一秒閃一次

**三個要注意的點：**

1. **沒有 reset**。FPGA 上電時 bitstream 會把正反器設成宣告的初始值
   （`reg cnt = 0`），所以閃燈可以省掉 reset 線。
   ⚠️ **這招只在 FPGA 有效，ASIC 一定要有 reset。**

2. **位元寬度用 `clog2` 算出來**，不要寫死 `[31:0]`。

3. **`led_fast` 是免費的** —— 直接拿計數器的高位元當輸出，一顆閘都不用。

> **★ 參數化的實際理由**：模擬時用 `CLK_HZ=200`，一下就跑完；
> 上板時用 `CLK_HZ=12_000_000`。同一份程式碼，改一個數字。
> 不參數化的話，模擬要跑一千兩百萬拍才看得到 LED 翻一次。

### 📁 `02_pwm` — 呼吸燈

數位電路怎麼做出「亮度」？**快速開關 + 視覺暫留**。

```
   工作週期 10%  →  ▁▁▁▁▁▁▁▁▁█   很暗
   工作週期 50%  →  ▁▁▁▁▁█████   一半
   工作週期 90%  →  ▁█████████   很亮
```

**兩個關鍵數字，而且互相拉扯：**

| | 算法 | 12MHz + 8 位元 |
|---|---|---|
| 解析度 | 2^PWM_BITS 階 | 256 階 |
| PWM 頻率 | CLK_HZ / 2^PWM_BITS | 46,875 Hz |

位元數越多 → 亮度越細膩，但 PWM 頻率越低。
16 位元的話 12M/65536 = 183Hz，**快速移動眼睛會看到殘影**。

> PWM 不只能控 LED —— 馬達轉速、加熱器功率、簡易音訊輸出，
> 用的都是同一顆電路。

### 📁 `03_button` — ★★ 上板子一定會踩到的三個坑

這是第 6 週去彈跳 + 第 7 週同步器的**實戰版**。

```
btn ──→[兩級同步器]──→[去彈跳]──→[邊緣偵測]──→ 計數器
        避免亞穩態     機械彈跳    按著不放
```

| 坑 | 症狀 | 解法 |
|---|---|---|
| **1. 亞穩態** | 電路**偶爾**亂跳，查不出原因 | 串兩級正反器 |
| **2. 機械彈跳** | 按一下加十幾 | 連續穩定 N 拍才承認 |
| **3. 按著不放** | 按住一秒加一千兩百萬 | 只在上升緣動作 |

> [!IMPORTANT]
> **★ 這三件事在每一個外部輸入上都要做**：按鍵、開關、感測器、
> 另一顆晶片來的訊號…… 只要不是同一個時脈域來的，就要走這三關。
>
> 亞穩態**不是理論問題，是真的會發生的物理現象**。
> 兩級同步器不是「降低機率」，是把失效時間拉長到幾百年一次。

### 📁 `04_seg7` — 四位數掃描顯示

**問題**：四位數要 4×8 = 32 支腳，板子只有 12 支。
**解法**：一次只點亮一位，快速輪流掃 —— 靠視覺暫留騙過眼睛。

> 這是「用時間換空間」最經典的例子，跟第 12 週「用延遲換吞吐量」
> 是同一種思路。

**掃描頻率怎麼選：**
- 太慢（< 60Hz × 位數）→ 看得到閃爍
- 太快（> 幾十 kHz）→ 每位亮的時間太短，整體變暗
- 常用值：每位 100~250Hz，四位數就是 400~1000Hz

> [!WARNING]
> **★ 這個範例的最高時脈只有 19.29 MHz —— 全週最慢，而且慢很多。**
>
> 原因就在這幾行：
> ```verilog
> wire [3:0] d0 =  value        % 10;
> wire [3:0] d1 = (value / 10)  % 10;
> ```
> 除法和取餘數**會合成出很大的電路**（第 11 週學過），
> 402 個邏輯單元裡絕大部分都花在這裡。
>
> 板子是 12MHz，19.29 MHz 勉強過關 —— 但**只剩 60% 餘裕**，
> 換個溫度或製程批次就可能不過。**練習 3 會叫你改掉它。**

⚠️ **共陽極 vs 共陰極**：本範例假設共陰極（1 = 亮）。
如果你的顯示器是共陽極，`seg` 要整個反相，否則會變成負片效果。

### 📁 `05_uart_tx` — 和外界通訊

```
   閒置  起始   d0  d1  d2  d3  d4  d5  d6  d7   停止  閒置
   ▔▔▔▔╲___╱▔╲__╱▔▔╲_╱▔▔▔▔╲___╱▔▔▔▔▔▔▔▔▔
        低一位  ← 先送最低位 (LSB first) →   高一位
```

**這顆 = 第 3 週的 PISO + 第 6 週的三段式狀態機 + 第 3 週的 tick 產生器。**
全部都是前面學過的東西組起來的。

**三個實戰重點：**

1. **鮑率誤差一定要算**
   12MHz / 115200 = 104.17 → 只能取 104，誤差 0.16%。
   UART 容許約 ±2%（10 位元累積不能超過半位元），所以沒問題。
   ⚠️ 誤差 3% 的話，前幾位還對後面就歪掉，症狀是「偶爾收到亂碼」，非常難查。

2. **`tx` 一定要上正反器**
   組合邏輯會有毛刺（第 7 週 `02_glitch`），一個毛刺就會被對方
   當成起始位元，整包資料錯掉。

3. **接收時要對齊到位元中央取樣**
   測試平台的 `receive_byte` 就是這樣做的：收到起始邊緣後先等
   1.5 個位元時間，才開始每隔 1 個位元時間取一次。

> **★ 上板之後**：燒進去，接 USB 轉序列埠，PuTTY 開 115200 8N1，
> 就會看到 `A B C … Z` 一秒一個跳出來。

## 五、練習題

### 練習 1
把 `01_blink` 改成**兩顆 LED 交替閃**（一顆亮時另一顆暗）。

提示：一行就好，不用改計數器。

### 練習 2
`02_pwm` 目前是線性呼吸（duty 等速增減），但**人眼對亮度的感覺是對數的**，
所以看起來會覺得「亮的時候變化慢、暗的時候變化快」。

改成用查表（ROM，第 9 週學的）存一組**伽瑪校正**過的亮度值，
讓呼吸看起來更自然。

### 練習 3 ★ 重要
`04_seg7` 因為用了除法，只能跑 19.29 MHz、吃掉 402 個邏輯單元。

改用 **雙重高低法（Double Dabble）** 演算法做二進位轉 BCD ——
只用位移和加法，不用除法。

改完重跑 `build.bat 04_seg7 seg7_top`，比較：
- 邏輯單元從 402 降到多少？
- 最高時脈從 19.29 MHz 升到多少？

> 這題把第 11 週（面積）、第 13 週（關鍵路徑）、本週（實測）三件事串起來，
> 是整份教材最值得做的練習之一。

### 練習 4
`05_uart_tx` 只能送。寫一個 **UART 接收器 `uart_rx`**，
把收到的位元組顯示在 LED 上。

提示：接收比發送難，因為你要自己**找出起始位元的邊緣**，
然後對齊到位元中央取樣（測試平台的 `receive_byte` 就是範本）。

### 練習 5（思考）
`build.bat` 裡 `nextpnr` 的參數是 `--freq 12`。
如果改成 `--freq 100`，`04_seg7` 會發生什麼事？

<details>
<summary>看答案</summary>

**會失敗**，因為它最高只能跑 19.29 MHz：

```
ERROR: Max frequency for clock 'clk': 19.29 MHz (FAIL at 100.00 MHz)
```

`--freq` 是**你給 nextpnr 的時序目標**，不是設定晶片跑多快。

它的作用是：
1. 讓 nextpnr 知道要多努力去最佳化佈局
2. 跑完之後告訴你「達成了沒有」

**所以 `--freq` 要填你板子上實際的時脈**（這裡是 12MHz）。
填太低，nextpnr 會偷懶（反正很容易達成）；
填太高，會浪費很多時間硬擠，最後還是失敗。
</details>
