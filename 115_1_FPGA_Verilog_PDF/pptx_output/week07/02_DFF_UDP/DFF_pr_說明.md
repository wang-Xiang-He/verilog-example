# 02_DFF_UDP 範例說明：自定序向邏輯 UDP（邊緣觸發 D 型正反器）

## 1. 這個範例在做什麼？

[01_Mux4_UDP](../01_Mux4_UDP/mux4_1pr_說明.md) 的 UDP 是組合邏輯（輸出只看現在的輸入）。
UDP 也可以描述**序向邏輯**（有記憶，輸出還要看「現在的狀態」），這就是**自定序向邏輯電路**（講義第 7、11 頁）。

本範例：用真值表定義一個**正緣觸發**的 D 型正反器 `DFF_pr`（講義第 11~13 頁）：CLK 由 0 變 1 時 Q = D，其餘時間 Q 不變。

---

## 2. 序向 UDP 的寫法

和組合 UDP 的差別（講義第 7 頁）：

| | 組合 UDP | 序向 UDP |
|---|---|---|
| 輸出宣告 | `output Y;` | `output Q;` **加上 `reg Q;`**（要記住狀態） |
| 真值表 | `輸入... : 輸出 ;` | `輸入... : 現在狀態 Q(n) : 下一狀態 Q(n+1) ;` |
| 新符號 | | `-`：下一狀態不變；`(01)`：轉換（邊緣） |
| 起始值 | | 可以用 `initial Q = 0;` 設定（見 [03_JKFF_UDP](../03_JKFF_UDP/JKF_pr_說明.md)） |

### 轉換（邊緣）的寫法
| 寫法 | 意思 |
|------|------|
| `(01)` | 0 → 1，正緣 |
| `(10)` | 1 → 0，負緣 |
| `(0?)` | 0 → 任何值（包含 0 → x 這種「不確定的正緣」） |
| `(?0)` | 任何值 → 0 |
| `(1?)` | 1 → 任何值 |
| `(??)` | 任何轉換 |

一行裡**最多只能有一個**輸入寫轉換。

### DFF_pr.v
```verilog
primitive DFF_pr (Q, D, CLK);
    output Q;
    reg    Q;
    input  D, CLK;

    table
    //  D   CLK  :  Q(n) :  Q(n+1)
        0  (01)  :   ?   :    0  ;   // 正緣 Q(n+1) = D (= 0)
        1  (01)  :   ?   :    1  ;   // 正緣 Q(n+1) = D (= 1)
        0  (0?)  :   0   :    0  ;   // 不確定的正緣：D 和 Q 一樣時，Q 不變
        1  (0?)  :   1   :    1  ;
        ?  (1?)  :   ?   :    -  ;   // 負緣：不變
        (??) ?   :   ?   :    -  ;   // D 改變但 CLK 沒有邊緣：不變（講義沒有，補上）
    endtable
endprimitive
```

## 3. 講義的兩個問題（實際用 ModelSim 驗證）

### (1) 第 12 頁「註解真值表衝突項」
講義第 11 頁有一行 `? (??) : ? : - ;`（CLK 任何轉換都不變），第 12 頁把它註解掉了。原因：
`(??)` 包含了 `(01)`，但第 1、2 行規定 `(01)` 時 Q 要變成 D，這一行卻說「不變」——**同一個輸入組合有兩種答案**。
把它打開，vlog 編譯就失敗：
```
** Error: DFF_pr.v(25): UDP table entry conflicts with earlier entry at DFF_pr.v(20)
```
所以第 12 頁改用 `? (1?) : ? : - ;`，只描述「CLK 從 1 變成其他值」。

### (2) 補上 `(??) ? : ? : - ;`：D 改變時怎麼辦？
序向 UDP 規定：**任何輸入的轉換，如果真值表裡找不到對應的行，輸出就變成 x**。
講義的表只描述了 CLK 的轉換，沒有描述「CLK 不動、D 改變」的情況。把補上的那一行刪掉再模擬：
```
t=10  CLK=1 D=0  ->  Q=0
t=15  CLK=0 D=1  ->  Q=x     ← D 一改變，Q 就變成 x
t=20  CLK=1 D=1  ->  Q=1
t=35  CLK=0 D=0  ->  Q=x
```
所以要加一行「D 有任何轉換、CLK 是任何準位時，Q 不變」。

> 講義第 13 頁的波形沒有出現 x，可能是當時的模擬器處理方式不同；用 ModelSim 一定要補上這行。

## 4. 預期輸出

CLK 一開始是 1，每 5ns 反相 → 正緣在 10、20、30 ...；D 在負緣（15、35 ...）改變。

```
t=0    CLK=1 D=0  ->  Q=x     ← 還沒遇到正緣（t=0 是 x→1，不算 0→1）
t=5    CLK=0 D=0  ->  Q=x
t=10   CLK=1 D=0  ->  Q=0     ← 正緣：Q = D = 0
t=15   CLK=0 D=1  ->  Q=0     ← D 變了，但不是正緣 → Q 不動
t=20   CLK=1 D=1  ->  Q=1     ← 正緣：Q = 1
...
t=35   CLK=0 D=0  ->  Q=1
t=40   CLK=1 D=0  ->  Q=0
...
t=75   CLK=0 D=1  ->  Q=0
t=80   CLK=1 D=1  ->  Q=1
...
t=100  CLK=1 D=0  ->  Q=0
```

### 觀察重點
- Q **只在 CLK 由 0 變 1** 時才跟著 D 變，和講義第 13 頁的 D=1 → Q=1、D=0 → Q=0 一樣。
- t=0 的 CLK 是從 x 變成 1，表裡的 `(01)` 不包含 `(x1)`，所以這不算正緣，Q 保持 x。
- 和 week03 的 [04_DFF](../../week03/04_DFF/dff_說明.md)（用 `always @(posedge clk)`）比較：結果一樣，但 UDP 要自己處理每一種轉換，比較麻煩。實務上正反器都用 `always` 寫，UDP 主要用在描述元件庫（cell library）。

---

## 5. 重點整理

| 觀念 | 說明 |
|------|------|
| 序向 UDP | 輸出宣告成 `reg`，表多一欄目前狀態 |
| `(01)` | 轉換（邊緣）；一行最多一個 |
| `-` | 下一狀態不變 |
| 衝突 | 同一組輸入有兩種答案 → 編譯錯誤 |
| 沒列到的轉換 | 輸出變 x，所以 D 的變化也要列 |
