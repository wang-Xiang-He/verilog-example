# 04_Encoder1 範例說明：優先權編碼器（for 迴圈寫法）

## 1. 先認識編碼器

講義第 14 頁：組合邏輯（Combination Logic）和循序邏輯（Sequential Logic）是數位系統的兩大分類，組合邏輯是最基礎、也最重要的部分。
本週從第 14 頁開始介紹常用的組合邏輯電路：**編碼器、解碼器、多工器、解多工器、比較器**。

### 編碼器（Encoder）（講義第 15 頁）
**編碼器**和解碼器相反：好幾條輸入線中**哪一條是 1**，就輸出那一條的**編號**（二進位）。
它具有 OR 的功能，能把多個輸入線「OR」成一個輸出。

一般的編碼器每次只允許一條輸入線啟動。**優先權編碼器（Priority Encoder）** 允許同時有好幾條是 1，並取**優先權最高**的那一條。

### 8 對 3 優先權編碼器的真值表
In[7] 優先權最高，In[0] 最低：

| In[7] | In[6] | In[5] | In[4] | In[3] | In[2] | In[1] | In[0] | Out[2:0] | None_ON |
|---|---|---|---|---|---|---|---|---|---|
| 1 | X | X | X | X | X | X | X | 111 | 0 |
| 0 | 1 | X | X | X | X | X | X | 110 | 0 |
| 0 | 0 | 1 | X | X | X | X | X | 101 | 0 |
| 0 | 0 | 0 | 1 | X | X | X | X | 100 | 0 |
| 0 | 0 | 0 | 0 | 1 | X | X | X | 011 | 0 |
| 0 | 0 | 0 | 0 | 0 | 1 | X | X | 010 | 0 |
| 0 | 0 | 0 | 0 | 0 | 0 | 1 | X | 001 | 0 |
| 0 | 0 | 0 | 0 | 0 | 0 | 0 | 1 | 000 | 0 |
| 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 000 | **1** |

- X = 不在乎：只要有更高位的 1，低位是什麼都沒關係。
- `None_ON = 1`：沒有任何輸入啟動。少了這個訊號，就分不出「In[0] = 1」和「全部是 0」，因為兩者的 Out 都是 000。

## 2. 程式說明

### Encoder1.v（講義第 16 頁）
```verilog
module Encoder1 (
    input      [7:0] In,
    output reg [2:0] Out,
    output reg       None_ON
);
    always @(*) begin : Encoder_Block       // 講義：always @(In)
        integer i;

        Out     = 0;                        // 設定初始值
        None_ON = 1;
        for (i = 0; i < 8; i = i + 1)
            if (In[i]) begin                // 傳回 Highest Bit 為 1 的位置
                Out     = i;
                None_ON = 0;
            end
    end
endmodule
```

### 具名區塊與區域變數
`begin : Encoder_Block` 替這個區塊取了名字（named block）。**只有具名區塊裡才可以宣告區域變數**，例如 `integer i;`（講義第 16 頁：使用 local variable 需加入 block name）。
不取名字，就要把 `integer i;` 宣告在模組層級。

### 設定初始值
迴圈開始前先設 `Out = 0`、`None_ON = 1`。如果全部輸入都是 0，迴圈裡的 `if` 一次都不成立，這兩個值就會保留下來。
少了這兩行，`Out` 在某些輸入下會沒有被賦值，合成時會產生 **latch**。

### 講義第 16 頁：「此種設計不好？」
講義問：當 `In = 11H = 0001_0001` 時，out = 0 還是 out = 4？（Maybe error?）

實際模擬的結果是 **4**，答案是正確的：
1. `i = 0`：In[0] = 1，Out = 0
2. `i = 4`：In[4] = 1，**Out 被蓋掉**，變成 4

迴圈從低位往高位掃，**後面（較高位）的 1 會蓋掉前面的**，所以最後留下來的是最高位。
這種寫法要靠「誰最後寫入」才會得到正確的優先權，讀程式的人不容易一眼看出來。

## 3. 預期輸出

前 10 組和講義第 17 頁的波形相同（00000000、00000001 ... 10000000、00000000）：

```
t=0    In=00000000  ->  Out=000 (0)  None_ON=1   ← 沒有輸入
t=10   In=00000001  ->  Out=000 (0)  None_ON=0   ← 和上一行的 Out 一樣，靠 None_ON 區分
t=20   In=00000010  ->  Out=001 (1)  None_ON=0
t=30   In=00000100  ->  Out=010 (2)  None_ON=0
...
t=80   In=10000000  ->  Out=111 (7)  None_ON=0
t=90   In=00000000  ->  Out=000 (0)  None_ON=1
t=100  In=00010001  ->  Out=100 (4)  None_ON=0   ← 11H：取高的 In[4]
t=110  In=10101010  ->  Out=111 (7)  None_ON=0   ← 講義第 17 頁畫面上的 10101010 → 111
```

### 觀察重點
- t=0 和 t=10 的 Out 都是 000，差別只在 None_ON。
- 0001_0001 的結果是 4，回答了講義第 16 頁的問題。

## 4. 重點整理

| 觀念 | 說明 |
|------|------|
| 編碼器 | 2ⁿ 條輸入 → n 位元編號 |
| 優先權編碼器 | 同時多個 1 時取優先權最高的 |
| None_ON | 區分「In[0] = 1」和「全部是 0」 |
| 具名區塊 | `begin : 名稱`，裡面才能宣告區域變數 |
| 先給初始值 | 避免沒被賦值而產生 latch |
| for 迴圈優先權 | 靠「後面蓋掉前面」，可讀性差 |
