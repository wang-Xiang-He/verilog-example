# 13_CFCPath_Delay 範例說明：條件式路徑延遲（範例練習 7-009）

## 1. 這個範例在做什麼？

**狀態相關路徑延遲（State-Dependent Path Delay，條件式延遲）**（講義第 39 頁）：
**若條件成立，則設定延遲時間；否則，則不設定延遲時間。**

真實元件的延遲常常和**當時的輸入狀態**有關，例如某顆晶片在某個控制腳是 1 的時候比較慢。
條件式延遲就是用來描述這種情況。

本範例（講義第 41 頁）：
1. 若 (a1 a2) = (11)，則路徑 a1 - y1 - y 與 a2 - y1 - y 均延遲 10 單位時間
2. 若 (a3 a4) = (11)，則路徑 a3 - y2 - y 與 a4 - y2 - y 均延遲 12 單位時間

---

## 2. 程式說明

### 語法（講義第 39 頁）
依並列或完全連接路徑分為兩種：
```
if (條件判斷式) (來源輸入埠 => 目的輸出埠) = 延遲時間;
if (條件判斷式) (來源輸入埠 *> 目的輸出埠) = 延遲時間;
```

### cfcpath_delay.v（講義第 41 頁）
```verilog
module cfcpath_delay (
    input  a1,
    input  a2,
    input  a3,
    input  a4,
    output y
);
    wire y1, y2;

    specify
        if ({a1, a2} == 2'b11) (a1, a2 *> y) = 10;
        if ({a3, a4} == 2'b11) (a3, a4 *> y) = 12;
    endspecify

    and and1 (y1, a1, a2);
    and and2 (y2, a3, a4);
    or  or1  (y,  y1, y2);
endmodule
```

### 和一般 if 不一樣的地方
- 這個 `if` 寫在 `specify` 裡，**不是**行為描述的 if，**不能接 `else`**。
- 條件裡只能用**輸入埠**（或 inout），不能用內部的 `y1`、`y2`。
- 條件在**輸入變化之後**判斷：用的是「變化後」的輸入值。
- 所有條件都不成立時，這次變化**沒有路徑延遲**（0 ns）。
  想給「其他情況」一個延遲，可以用 `ifnone (a1 => y) = 2;`。

---

## 3. 預期輸出

```
t=0    a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0    ← 條件不成立 → 沒有延遲，t=0 就是 0
t=20   a1=1 a2=1 a3=0 a4=0  |  y1=1 y2=0  |  y=0    ← a1a2 = 11，條件 1 成立
t=30   a1=1 a2=1 a3=0 a4=0  |  y1=1 y2=0  |  y=1    ← 延遲 10
t=40   a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0    ← a1a2 變 00，條件不成立 → y 立刻變 0
t=60   a1=0 a2=0 a3=1 a4=1  |  y1=0 y2=1  |  y=0    ← a3a4 = 11，條件 2 成立
t=72   a1=0 a2=0 a3=1 a4=1  |  y1=0 y2=1  |  y=1    ← 延遲 12
t=80   a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0    ← 立刻變 0
t=100  a1=1 a2=1 a3=1 a4=1  |  y1=1 y2=1  |  y=0    ← 兩個條件都成立
t=110  a1=1 a2=1 a3=1 a4=1  |  y1=1 y2=1  |  y=1    ← 取最短的 10
t=120  a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0    ← 立刻變 0
```

### 觀察重點
- **y 變 1 時有延遲**（20→30、60→72、100→110）：此時輸入是 11，條件成立。
- **y 變 0 時沒有延遲**（t=40、80、120 立刻變 0）：輸入已經變回 00，條件不成立，這次變化沒有路徑延遲。
- **t=0 的 y 直接是 0**，不像 11、12 範例一開始有 10 ns 的 x。
- 和 [12_FCPath_Delay](../12_FCPath_Delay/fcpath_delay1_說明.md) 對照：12 的 y 在 50、92、130 才變 0，這裡在 40、80、120 就變 0。
  上升的時間兩者相同。

### 和其他路徑延遲範例的比較

| 輸入變化 | 11 / 12（無條件） | 13（條件式） |
|---------|------------------|-------------|
| 20：a1a2 → 11 | y 在 30 變 1 | y 在 30 變 1 |
| 40：a1a2 → 00 | y 在 **50** 變 0 | y 在 **40** 變 0 |
| 60：a3a4 → 11 | y 在 72 變 1 | y 在 72 變 1 |
| 80：a3a4 → 00 | y 在 **92** 變 0 | y 在 **80** 變 0 |

---

## 4. 重點整理

| 觀念 | 說明 |
|------|------|
| `if (條件) (來源 *> 目的) = 延遲;` | 條件成立才有延遲 |
| 條件 | 只能用輸入埠，用的是變化後的值 |
| 不能接 else | 其他情況用 `ifnone` |
| 條件都不成立 | 沒有路徑延遲（0） |
| 用途 | 描述延遲會隨輸入狀態改變的元件 |
