# 11_PPath_Delay 範例說明：並列路徑延遲 specify / =>（範例練習 7-005）

## 1. 這個範例在做什麼？

前面幾個範例把延遲設在**每個閘或每條線**上，要算總延遲得一級一級加。
**Module Path Delay（模組路徑延遲）** 換個角度：直接規定「**從哪個輸入埠到哪個輸出埠，要花多少時間**」，
不管裡面經過幾個閘（講義第 32~35 頁）。

元件的資料手冊（datasheet）通常就是這樣標示的：「A 腳到 Y 腳的傳遞延遲 10 ns」。

```
                 路徑 a1 - y1 - y：延遲 10 單位時間
a1 ─┐            路徑 a2 - y1 - y：延遲 10 單位時間
    AND1 ── y1 ─┐  路徑 a3 - y2 - y：延遲 12 單位時間
a2 ─┘           │  路徑 a4 - y2 - y：延遲 12 單位時間
                OR1 ── y
a3 ─┐           │
    AND2 ── y2 ─┘        （邏輯閘本身都不設延遲）
a4 ─┘
```

## 2. specify 區塊的語法

延遲寫在 `specify ... endspecify` 裡，有兩種格式（講義第 32 頁）：

| 格式 | 寫法 | 意思 |
|------|------|------|
| 並列路徑 | `(來源 => 目的) = 延遲;` | **一對一**：來源第 0 位 → 目的第 0 位、第 1 位 → 第 1 位 … |
| 完全連接路徑 | `(來源1, 來源2 *> 目的) = 延遲;` | **每一個**來源到**每一個**目的都有路徑（見 [12_FCPath_Delay](../12_FCPath_Delay/fcpath_delay1_說明.md)） |

```
 (a) 並列路徑 =>          (b) 完全連接路徑 *>
 in[0] ───────► out[0]    in[0] ──┬──┬──► out[0]
 in[1] ───────► out[1]    in[1] ──┼──┼──► out[1]
 in[2] ───────► out[2]    in[2] ──┴──┴──► out[2]
                                  （每個輸入都連到每個輸出）
```

本範例用**並列路徑** `=>`。

### ppath_delay1.v（講義第 34 頁）
```verilog
module ppath_delay1 (
    input  a1,
    input  a2,
    input  a3,
    input  a4,
    output y
);
    wire y1, y2;

    specify
        (a1 => y) = 10;             // 路徑 a1 - y1 - y，延遲 10 單位時間
        (a2 => y) = 10;
        (a3 => y) = 12;             // 路徑 a3 - y2 - y，延遲 12 單位時間
        (a4 => y) = 12;
    endspecify

    and and1 (y1, a1, a2);          // 邏輯閘本身沒有延遲
    and and2 (y2, a3, a4);
    or  or1  (y,  y1, y2);
endmodule
```

規則：
- 來源必須是 `input`（或 `inout`），目的必須是 `output`（或 `inout`）；**不能**拿內部的 `y1` 當路徑端點。
- `=>` 的來源和目的**位元數要一樣**（一對一對應）。這裡都是 1 位元。
- 延遲的單位一樣由 `` `timescale `` 決定。
- `specify` 和其他延遲一樣，**只在模擬有效**，合成時忽略。

## 3. 預期輸出

```
t=0    a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=x    ← y1、y2 沒延遲，立刻是 0
t=10   a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0    ← 路徑延遲 10
t=20   a1=1 a2=1 a3=0 a4=0  |  y1=1 y2=0  |  y=0
t=30   a1=1 a2=1 a3=0 a4=0  |  y1=1 y2=0  |  y=1    ← a1a2 → y：10ns
t=40   a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=1
t=50   a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0
t=60   a1=0 a2=0 a3=1 a4=1  |  y1=0 y2=1  |  y=0
t=72   a1=0 a2=0 a3=1 a4=1  |  y1=0 y2=1  |  y=1    ← a3a4 → y：12ns
t=80   a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=1
t=92   a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0
t=100  a1=1 a2=1 a3=1 a4=1  |  y1=1 y2=1  |  y=0
t=110  a1=1 a2=1 a3=1 a4=1  |  y1=1 y2=1  |  y=1    ← 四個同時變：取最短的 10ns
t=120  a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=1
t=130  a1=0 a2=0 a3=0 a4=0  |  y1=0 y2=0  |  y=0
```

### 觀察重點
- **y1、y2 和輸入同時變**：邏輯閘本身沒有延遲，延遲只加在「輸入埠 → 輸出埠」的路徑上。
- y 的延遲由**哪個輸入造成變化**決定：a1a2 造成的晚 10 ns（講義第 35 頁的 #10），a3a4 造成的晚 12 ns（#12）。
- t=100、t=120：四個輸入**同時**變，兩條路徑都可能是原因，模擬器取**最短**的 10 ns。
- t=0~10 的 y 是 x：輸出還沒經過路徑延遲。

## 4. 重點整理

| 觀念 | 說明 |
|------|------|
| `specify ... endspecify` | 模組路徑延遲區塊 |
| `(來源 => 目的) = 延遲;` | 並列路徑，一位元對一位元 |
| 端點 | 只能是模組的輸入埠 / 輸出埠 |
| 和閘延遲比較 | 直接規定埠到埠的總延遲，不用一級一級加 |
| 同時變化 | 多條路徑同時觸發時取最短的延遲 |
