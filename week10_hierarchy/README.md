## 一、兩種設計方向（課本 3.7.1）

| | 由上而下 Top-Down | 由下而上 Bottom-Up |
|---|---|---|
| 怎麼做 | 先定義頂層介面，再往下切 | 先做好零件，再往上組 |
| 適合 | 全新的系統、規格已經確定 | 手上已經有現成模組可以重用 |
| 風險 | 切到底層才發現介面不合 | 組起來才發現整體效能不行 |
| 實務 | **兩個一起用** —— 頂層由上而下規劃，零件由下而上累積 | |

本週的 `01_alu_hier` 是由上而下（先有 ALU 規格，再切三個單元），
`03_top_integration` 是由下而上（前幾週的模組都做好了，這週組起來）。

## 二、埠對應的兩種寫法（課本 3.7.2）

```verilog
// ✅ 具名對應（named）—— 一律用這種
alu_arith u_arith (
    .a      (a),
    .b      (b),
    .sub    (op[0]),
    .result (w_arith),
    .carry  (w_carry)
);

// ❌ 位置對應（positional）—— 不要用
alu_arith u_arith (a, b, op[0], w_arith, w_carry);
```

**為什麼位置對應不能用：**

- 子模組的埠順序一改，所有實例**默默接錯**，編譯完全不會報錯
- 埠一多就數不清第幾個是第幾個
- 別人讀你的程式碼要一直翻回子模組定義

> [!TIP]
> 用不到的輸出埠可以留空：`.fall()`。
> 輸入埠不能留空（會變成浮空的 z），要明確接 `1'b0` 或 `1'b1`。

## 三、★★ 本週核心：資料路徑 + 控制器

這是**整個數位設計最重要的架構模式**，大到 CPU、小到洗衣機控制板都一樣。

```
    ┌────────────┐   控制訊號    ┌──────────────┐
    │ Controller │─────────────→│   Datapath   │
    │   (FSM)    │              │ (暫存器 + ALU) │
    │            │←─────────────│              │
    └────────────┘   狀態旗標    └──────────────┘
```

| | 控制器 Controller | 資料路徑 Datapath |
|---|---|---|
| 負責 | **什麼時候**做什麼 | **怎麼**算 |
| 內容 | 一台狀態機 | 暫存器、加法器、多工器 |
| 看得到資料嗎 | ❌ 只看得到旗標 | ✅ 資料都在這 |
| 知道現在第幾步嗎 | ✅ 就是它在管 | ❌ 完全不知道 |

`02_datapath` 的移位相加乘法器，兩者之間**只有 3 條線**：

```
控制器 → 資料路徑：  load（吃新資料）、shift_add（做一次運算）
資料路徑 → 控制器：  cnt_done（我數完 8 次了）
```

**這樣分的四個好處：**

1. 要改運算方式 → 只動 datapath
2. 要改流程 → 只動 controller
3. 兩個人可以**同時開發**，先講好中間那幾條線就好
4. 出錯時一眼看得出是「算錯」還是「時序錯」

> 第 16 週的期末專題「簡易 8-bit CPU」就是這個架構放大：
> 控制器 = 指令解碼器，資料路徑 = 暫存器檔 + ALU。

## 四、本週四個範例

### 📁 `01_alu_hier` — 把 ALU 拆成四顆
```
iverilog -o sim.out 01_alu_hier.v 01_alu_hier_tb.v
echo %ERRORLEVEL%
vvp sim.out
gtkwave 01_alu_hier.gtkw
```
**看什麼**：★ 波形上 `w_arith`、`w_logic`、`w_shift` **三條同時都有值**。
三顆單元一直都在算，多工器只是挑一個送出去。

這是硬體和軟體最根本的差別：軟體的 `if-else` 只執行中的那條，
硬體**每條路都在跑**，多花的是面積不是時間。

**和第 3 週 `12_alu` 的對照：**

| | 平的一顆 | 分成四顆 |
|---|---|---|
| 讀程式碼 | 一路往下讀 | 要跳來跳去 |
| 改一個功能 | 要小心動到別的 | 只改那一顆 |
| 重複使用 | 整顆搬走 | 可以只拿 `alu_arith` |
| 波形除錯 | 只看得到輸入輸出 | ★ 每個中間結果都看得到 |
| 綜合面積 | 幾乎一樣 | 幾乎一樣 |

> **★ 分層不會讓電路變快或變小。** 它換到的是「人看得懂」和「改得動」。

### 📁 `02_datapath` — ★★ 本週最重要
```
iverilog -o sim.out 02_datapath.v 02_datapath_tb.v
echo %ERRORLEVEL%
vvp sim.out
gtkwave 02_datapath.gtkw
```
**看什麼**：`mplier` 每拍往右掉一位，最低位是 1 的時候 `acc` 才會加。
這就是小學的直式乘法，只是換成二進位。

實測（13 × 11）：
```
   拍 | 狀態 | mplier    mcand      acc
   ---+------+---------------------------
    0 |  1   | 00001011 00001101     0
    1 |  1   | 00000101 00011010    13    ← bit0=1，加了
    2 |  1   | 00000010 00110100    39    ← bit0=1，加了
    3 |  1   | 00000001 01101000    39    ← bit0=0，沒加
    4 |  1   | 00000000 11010000   143    ← bit0=1，加了
```

### 📁 `03_top_integration` — 系統整合
```
iverilog -o sim.out 03_top_integration.v 03_top_integration_tb.v

vvp sim.out
gtkwave 03_top_integration.gtkw
```

把五個前幾週的模組接成一台按鍵計數器：

**看什麼**：★ 打開設計檔看 `top_integration` 模組本身 ——

## 五、`parameter` vs `localparam`

```verilog
module foo #(
    parameter WIDTH = 8              // ✅ 可以從外面覆寫
) (...);
    localparam ADDR_BITS = clog2(WIDTH);   // ✅ 算出來的，不開放覆寫
```

**規則**：凡是**由別的參數推導出來**的值，一律用 `localparam`。

**理由**：如果 `ADDR_BITS` 開放覆寫，別人可能傳進 `WIDTH=16` 但 `ADDR_BITS=2`
這種自相矛盾的組合，而且**編譯不會報錯**。這種 bug 最難找。

> [!WARNING]
> 課本 11.3.1 提到的 `defparam u8.WIDTH = 16;` 是 **Verilog-1995 的舊寫法**。
> Verilog-2001 之後不建議使用，SystemVerilog 直接標成 deprecated。
> **一律用 `#(.NAME(value))`。**

## 六、命名規範（實務慣例）

課本沒細講，但業界都這樣做，跟著用不會錯：

| 對象 | 慣例 | 例子 |
|---|---|---|
| 模組實例 | `u_` 開頭 | `u_arith`、`u_ctrl` |
| 模組之間的連線 | `w_` 開頭 | `w_arith`、`w_carry` |
| 暫存器 | `_r` 結尾 | `sipo_r`、`dout_r` |
| 低準位有效 | `_n` 結尾 | `rst_n`、`cs_n` |
| generate 標籤 | 有意義的名字 | `: bit_slice` |

> generate 的 `begin` **一定要給標籤**，否則階層路徑會變成
> 看不懂的 `$gen_block_1`，波形上根本找不到東西。

### 練習 3
`03_top_integration` 的計數器只有 4 位元（0~15）。
改成兩位數（0~99），用兩個 `seg7_decoder` 分別顯示十位和個位。

### 練習 4（思考）
下面這樣寫會發生什麼事？

```verilog
adder_n #(.N(8)) u_add (
    .a(a), .b(b), .cin(1'b0), .sum(sum)
);
```

<details>
<summary>看答案</summary>

`cout` 沒接。這是**合法**的，編譯不會報錯，只會有個 warning。

輸出埠留空的意思是「這個輸出我不要」，綜合工具會把只驅動它的邏輯最佳化掉。
在這個例子裡沒問題，因為 `cout` 只是加法器最後一級的進位。

**但輸入埠留空就完全不同**：那條線會變成浮空的 `z`，
所有跟它有關的運算全部變 `x`，而且**編譯一樣不報錯**。

所以：輸出可以留空，**輸入永遠要接**。
</details>
