## 一、數字怎麼寫

```verilog
8'b1010_0101      // 二進位   （底線只是給人看，電腦忽略）
8'hA5             // 十六進位
8'd165            // 十進位
8'o245            // 八進位
```

**四個都是同一個值 165。**

格式固定是：

```
<幾位元> ' <進位> <值>
   8      '   h    A5
```

> [!WARNING]
> **位元寬度非常重要。** `4'd15` 和 `8'd15` 值一樣，但一個是 4 條線、一個是 8 條線。
> 寬度不夠會被無聲截斷 —— 這是初學最常見的 bug。
>
> ```verilog
> wire [3:0] x = 8'd200;   // 200 裝不進 4 位元 → 只留低 4 位 = 8
> ```

## 二、切片與串接

| 寫法 | 意思 |
|---|---|
| `a[7:4]` | 取第 7 到第 4 位（4 條線） |
| `a[0]` | 取第 0 位（1 條線，**不用冒號**） |
| `{a, b}` | 把 a、b 兩束線**接成一束**（a 在高位） |
| `{2{a}}` | 把 a **複製兩次** |
| `{{4{a[3]}}, a}` | 符號延伸（把最高位複製 4 次接在前面） |

> [!NOTE]
> 大括號 `{}` 在 Verilog 裡是「**把線黏在一起**」，
> **不是**其他語言的程式區塊。程式區塊用 `begin` / `end`。

## 三、五類運算子（最容易搞混的地方）

| 類別 | 符號 | 輸出寬度 | 說明 |
|---|---|---|---|
| 算術 | `+ - * / %` | 跟輸入一樣或更寬 | 會被綜合成加法器/乘法器 |
| **位元** | `& \| ^ ~` | **跟輸入一樣寬** | 一位一位分別做 |
| **邏輯** | `&& \|\| !` | **永遠 1 位元** | 把整條線當成一個真假值 |
| 關係 | `== != < > <= >=` | 永遠 1 位元 | 比較 |
| **縮減** | `&a \|a ^a` | **永遠 1 位元** | 把一整條線縮成一個位元 |
| 位移 | `<< >>` | 跟輸入一樣寬 | 左移 = 乘 2，右移 = 除 2 |

### ★ 最重要的一組對照

```verilog
a = 4'b1100;
b = 4'b1010;

a & b   = 4'b1000    // 位元 AND：4 個 AND 閘，輸出 4 位元
a && b  = 1'b1       // 邏輯 AND：a 非零 且 b 非零 → 1 位元
&a      = 1'b0       // 縮減 AND：a[3]&a[2]&a[1]&a[0]
```

**三個都用到 `&`，意義完全不同。** 這是本週最需要記熟的。

### 縮減 XOR 的實用價值

```verilog
^a    // a 裡面 1 的個數是奇數 → 1，偶數 → 0
```

這就是**同位元檢查（parity）**，資料傳輸偵錯的基本手段。一行搞定。

## 四、★ 四值邏輯 0 / 1 / x / z

Verilog 的線不是只有 0 和 1，還有兩個狀態：

| 值 | 意思 | 什麼時候出現 | 波形上長怎樣 |
|---|---|---|---|
| `0` | 低電位 | 正常 | 低的線 |
| `1` | 高電位 | 正常 | 高的線 |
| **`x`** | **不知道** | reg 沒給初值、reset 沒接、兩個東西搶同一條線 | **紅色** |
| **`z`** | **高阻抗（浮空）** | 線沒接、三態緩衝器關掉 | **中間高度的線** |

> [!IMPORTANT]
> **這是你以後最重要的除錯線索。**
>
> - 波形一片**紅色 x** → 通常是忘了給初值，或 reset 沒接好
> - 波形出現**中線 z** → 通常是忘了接線，或三態沒開 enable
>
> 而且 x 和 z 會**傳染** —— 一個 x 進到運算裡，整串結果都變 x。
> 所以要往**最左邊、最上游**找源頭，不是看最後那條。

### 練習 3（思考）
下面這行有什麼問題？

```verilog
wire [3:0] sum;
assign sum = 4'd9 + 4'd8;
```

<details>
<summary>看答案</summary>

9 + 8 = 17，但 `sum` 只有 4 位元，最多裝到 15。
17 的二進位是 `10001`，5 位元 —— 最高位被砍掉，只剩 `0001` = 1。

**答案會是 1，不是 17。** 而且模擬器不會警告你。

修法：`wire [4:0] sum;` —— 加法的結果要比輸入多一位元。
這就是為什麼 `02_operators.v` 裡 `o_add` 宣告成 5 位元。
</details>
